Why TeamAI

Not another AI coding tool

TeamAI is different — it orchestrates the actual claude CLI binary, not the API. Each agent gets its own Claude subprocess, its own git worktree, and its own role persona. No API keys, no token limits, no vendor lock-in.

🖥️

CLI-Native

Spawns real claude CLI subprocesses with stream-json I/O. Full access to the filesystem, git, and shell — no API abstraction layer.

🐳

Container Isolation

Each agent runs inside a Docker devcontainer with VS Code devcontainer.json support, ensuring reproducible, sandboxed execution environments.

⚡

Parallel Agents

Multiple agent sessions run simultaneously with git worktree isolation — planner and coder work in parallel without conflicts.

🌐

Multi-Project

Manage multiple codebases from a single UI. Each project has its own .teamai/ state and .claude/ configuration.

🔌

WebSocket Streaming

Real-time agent output streams to the browser via WebSocket. Watch each agent think, plan, and code in real time.

🔧

Customizable Roles

Define your own agent roles and command templates — analyst, planner, coder, QA reviewer, merger — or create new ones.

Auto Mode

Hands-off pipeline execution

Enable Auto Mode and TeamAI autonomously picks tasks from the backlog, respects dependency ordering, runs them through the pipeline, auto-approves at the review stage, creates PRs, polls CI, and auto-merges when all checks pass.

  • Configurable max parallel tasks
  • Dependency-aware task selection (blocks incomplete deps)
  • Auto-approve at awaiting-review → create PR
  • CI polling via gh pr view → auto-merge on green
  • Auto-done tasks highlighted for later manual review

Pipeline Internals

What agents do vs. what the orchestrator handles

Not every pipeline step needs an AI agent. The orchestrator handles mechanical operations directly with coded logic — git operations, CLI commands, file checks — only spawning Claude agents where semantic understanding is required.

📋

Spec Phase

Agent: Analyst writes spec.md from the task description.
Code: Log rotation, phase headers, revision-mode detection.

📐

Plan Phase

Agent: Planner reads the spec and produces plan.json.
Code: Worktree creation, git pull, phase cascading.

⚙️

Implement Phase

Agent: Coder (one per subtask) implements changes, runs tests, commits.
Code: Worktree isolation, scope violation detection, deliverable verification, cherry-pick orchestration, git push with remote HEAD verification, sensor gates.

🔍

QA Review Phase

Agent: QA Reviewer validates implementation against spec, writes qa_report.json.
Code: Locked-report detection, unpushed-commit precheck with auto-push, FAIL-type routing (cleanup / spec_concerns), max-attempt circuit breaker.

🔀

Create PR Phase

Agent: None — direct CLI.
Code: Rebase, artifact commit, gh pr create / glab mr create, PR body generation, URL extraction. Agent only spawned if rebase has conflicts.

🔀

Merge Phase

Agent: None if clean — only on conflict.
Code: Rebase, artifact commit, pre-merge sensors, git merge --no-edit, worktree removal. Merger agent spawned only if merge conflicts.

🧠 Smart delegation: 5 sessions → 3 per clean pipeline run

Before optimization, every pipeline run spawned 5 Claude sessions (spec, plan, implement, create-pr, merge). After replacing mechanical agent work with direct CLI calls, the clean path now uses only 3 — spec, plan, and implement. PR creation and conflict-free merges are fully automated. Agents are reserved for work that genuinely requires semantic understanding: writing specifications, decomposing tasks, authoring code, reviewing quality, and resolving merge conflicts.

🔄 Two-tier conflict resolution pattern

All conflict-resolution paths follow the same pattern: try the direct command first (coded), spawn a merger agent only on conflict (AI). Applied in three places — rebase conflicts, cherry-pick conflicts, and merge conflicts. This keeps the happy path fast (no agent spawn) while preserving semantic conflict resolution for the edge cases where it's needed.
