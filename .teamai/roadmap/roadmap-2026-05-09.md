## Executive Summary

TeamAI is a self-hosted Next.js web application that orchestrates multi-agent Claude Code CLI workflows — replacing what would otherwise be manual, single-agent Claude sessions with a browser-based pipeline manager. The product is in early-stage development (v0.1.0) with a functioning core: Kanban board with drag-and-drop, WebSocket-based live streaming, 9-column pipeline (spec → plan → implement → QA → review → merge), devcontainer isolation, and PTY terminal sessions. The immediate priorities are hardening the pipeline against failures (P0), closing competitive feature gaps around multi-LLM support and autonomous execution (P1), and building the foundations for production readiness — test coverage, collaboration, and CI/CD integration (P2). The product is uniquely positioned as a self-hosted, private alternative to cloud-based AI coding agents like Devin, appealing to teams that value data sovereignty and customizable agent personas.

## Ideation Findings Summary

The ideation scan of the TeamAI codebase (~7 library modules, 22 components, 5 page routes) identified the following key areas:

**Architecture strengths:**
- Clean separation of concerns: ProcessManager (subprocess I/O) → Orchestrator (pipeline logic) → TaskStore (persistence) → Server Actions (API surface)
- WebSocket-based real-time updates with NDJSON streaming — robust even for chunked output
- Provider system with per-role model overrides (Anthropic, Bedrock, Vertex, Ollama)
- Per-project isolation via `.teamai/` state directories and git worktrees
- Devcontainer support for sandboxed agent execution

**Gaps & tech debt:**
- No authentication or access control (local-only by design, but no guardrails)
- Zero test coverage — no unit, integration, or E2E tests exist
- Pipeline error recovery is basic: rate-limit handling works, but process crashes leave stale state
- Git worktree isolation is implemented inconsistently — always creates worktrees, even for tasks that don't need them
- Terminal feature described as "not yet wired up" despite xterm.js and node-pty being installed
- README is stock Next.js template — no documentation for users or contributors
- No database — all state is filesystem JSON (fine for single-user, doesn't scale)

## Competitive Positioning

### Devin (Cognition AI)
- **Where they're ahead:** Fully autonomous, managed cloud sandbox, polished dashboard with productivity metrics, team collaboration, multi-LLM, VS Code extension
- **Where we're ahead:** Self-hosted privacy, customizable agent roles/personas, no vendor lock-in for LLM (bring your own key), drag-and-drop pipeline control, much lower cost
- **Their audience:** Teams wanting a turnkey AI developer with minimal setup
- **Our audience:** Developers who want control over their AI pipeline, data privacy, and custom agent behaviors
- **Gaps they're ignoring:** Fully local/air-gapped operation, per-agent role customization, human-in-the-loop pipeline control with UI

### CrewAI
- **Where they're ahead:** Mature role-based multi-agent framework, Python ecosystem integrations, any LLM support, large community
- **Where we're ahead:** Web UI with drag-and-drop, built-in pipeline phases, git integration, terminal access, no coding required to use
- **Their audience:** Python developers building custom agent workflows
- **Our audience:** Any developer who wants a ready-to-use pipeline without writing agent orchestration code

### OpenHands
- **Where they're ahead:** Secure Docker sandbox, multi-LLM backends, browser-based code editor, larger open-source community
- **Where we're ahead:** Multi-agent role pipeline (not just single-agent), git worktree isolation per task, PTY terminal access, customizable command/role templates
- **Gaps both share:** Neither has multi-user support, neither has robust reporting/analytics

### GitHub Copilot Workspace
- **Where they're ahead:** Deep GitHub integration (issues, PRs, code review), Microsoft backing, spec-driven development UX
- **Where we're ahead:** Provider flexibility (not locked to GitHub/OpenAI), self-hosted, customizable agents, devcontainer support
- **Gap to exploit:** Teams using non-GitHub repos (GitLab, Bitbucket, self-hosted Git) have no Copilot Workspace option

## Summary — Top 10 Highest-Priority Items

1. **P0** Pipeline crash recovery — stale sessions and orphaned worktrees can corrupt state
2. **P0** Concurrent task editing lock — two agents could write to the same task's files
3. **P0** Fix terminal feature — xterm.js is installed but the feature is incomplete
4. **P0** Pre-commit quality gates — no automated checks exist before commits
5. **P1** Multi-LLM support — the single biggest competitive gap vs. every competitor
6. **P1** Autonomous mode — Devin's core differentiator; users expect this
7. **P1** Test suite — zero test coverage is a risk for any further development
8. **P1** GitLab + Bitbucket — unlocks the "non-GitHub" market where Copilot Workspace can't compete
9. **P1** Browser testing in QA — Playwright MCP is already configured, just needs pipeline integration
10. **P2** Database persistence — filesystem JSON won't scale past ~100 tasks or multi-user access
